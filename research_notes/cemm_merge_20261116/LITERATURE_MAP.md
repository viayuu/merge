# 模型合并文献地图：围绕你的 URS 问题整理

2026-11-16。以下 20 组核心方法覆盖两个对话中的主线；再补充 2 篇平均/插值背景、3 篇能力迁移应用及 URS/MPSF-FL/MoSES 三项项目相关文献，共 28 项。SLERP 单列为工程算子，不虚构为一篇新的模型合并论文。

核对深度不同：CEMM 已读全文、附录和补充实现；PCB/WUDI/AdaMerging/TSV/Git Re-Basin 补齐本地 PDF 并核对方法；其他方法核对本地既有论文或原论文网页的相关章节/摘要。具体覆盖见 [COVERAGE.json](COVERAGE.json)。没有把所有论文都宣称为代码级复现。

## 1. 先分清四个条件

1. **训练谱系**：专家是否从同一个、已经训练过的 checkpoint 微调？共同随机初始化只是其中另一种设置。
2. **计算输入**：运行合并公式是否需要显式提供 base？不需要这个文件，并不代表参数自动对齐。
3. **额外信息与计算**：只读权重，还是需要激活/Fisher/无标签实例/任务评估？不用原训练集，不等于不用数据；不训练 policy，不等于不做梯度或搜索。
4. **最终交付**：是否真正只有一套固定参数？任务掩码、多头、动态专家和多模型集成应分别标注。

统一记号：θ₀ 是参考模型，θᵢ 是专家，τᵢ=θᵢ−θ₀ 是任务增量。这个减法可以对任意同形状参数计算，但只有明确训练谱系及可比较坐标时，才有“从共同起点学到的任务更新”的解释。

## 3. 直接平均与任务增量：为什么不能只看公式中有没有 base
 
Model Soups 的基本式为 θₘ=Σαᵢθᵢ，通常 αᵢ≥0 且和为 1。它不会增加最终推理参数量。Greedy soup 先按验证表现排序，再尝试纳入模型，保留带来改善的成员。原论文主要是在同一预训练模型上以不同微调配置获得的一组模型，不是对任意跨任务独立训练模型的保证。[原文](https://proceedings.mlr.press/v162/wortsman22a.html)

Task Arithmetic 为 θₘ=θ₀＋λΣ(θᵢ−θ₀)。展开后是 λΣθᵢ＋(1−Kλ)θ₀，因此 λ=1/K 时 base 完全抵消，严格等于均值。其他尺度仍受参考点影响。经典实验用共同预训练来源，当前 URS 重建随机起点应标成迁移探索。[原文](https://arxiv.org/abs/2212.04089)

CEMM 示例中位数也有平移不变性：θ₀＋median(θᵢ−θ₀)=median(θᵢ)。这两个等式说明“算式是否需要 base”与“源模型是否适合合并”必须分开判断。

## 4. 哪些更新应该保留

**TIES。** 先对每个 τ 裁剪较小坐标，再按剩余增量的合计符号确定方向，仅对同方向的非零增量合并。符号选择不等于简单数专家票数；例如两个 +0.1 与一个 −2 的合计符号仍为负。它处理坐标级冲突，不会辨认一个坐标是否真的对应同样的功能。[原文](https://arxiv.org/abs/2306.01708)

**DARE。** 对每个增量坐标随机采样保留掩码 m，写成 τ̃=m⊙τ/(1−p)。删除的是微调增量，未删除部分通过重缩放补偿。E[τ̃]=τ 是参数层面的等式，不代表非线性模型输出或路线成本的期望不变。它是稀疏化插件，可与不同合并规则组合。[原文](https://proceedings.mlr.press/v235/yu24p.html)

**PCB。** 在参数维度上结合两个分数：

\[
\beta_{\mathrm{intra},i}=\operatorname{Softmax}\bigl(K\operatorname{Norm}(\tau_i\odot\tau_i)\bigr),\quad
\beta_{\mathrm{inter},i}=\sum_j\operatorname{Softmax}\bigl(\operatorname{Norm}(\tau_i\odot\tau_j)\bigr).
\]

二者相乘，保留高分坐标，再做加权增量合并。平方幅度使较大更新在专家内部倾向获得更高评分；跨专家乘积又考虑同一坐标的相对兼容性。因此最终不是简单“谁改得最大就听谁的”，也不是硬性同号投票。这里是论文公式解释，不替代具体归一化实现。[原文 §3](https://arxiv.org/html/2410.02396v1#S3)

例如 τ₁=(0.2,0.01,−0.1)，τ₂=(0.15,−0.02,0.08)：第一个位置双方更新较大且同向；第三个位置各自幅度不小却方向相反。这说明幅度与兼容性提供不同信号，不能由单个分数证明实际任务贡献。PCB+ES 另用验证评价与 CMA-ES 搜专家系数，应与基础权重规则分开记成本。

**Breadcrumbs。** 逐层去掉两端的更新：很小的扰动，以及幅度最大的异常值，保留中间范围。它与 TIES“保留大更新”、DARE“随机保留”形成不同筛选假设。[原文](https://arxiv.org/abs/2312.06795)

**TALL-Masks / Consensus。** 用专家增量和多任务增量的关系找出任务支持，再通过掩码恢复专门能力；Consensus Merging 进一步用跨任务支持情况筛除不利于共享的更新。任务切换时应用不同 mask 属于压缩/恢复方案，不能将其成绩直接称为一套不变参数的多任务成绩。[原文](https://proceedings.mlr.press/v235/wang24k.html)

## 5. 怎样保持专家的行为，而不只保持数值

**Fisher Merging。** 每个坐标按 Fisher 信息加权：

\[
\theta_{m,j}=\frac{\sum_i\alpha_i F_{i,j}\theta_{i,j}}{\sum_i\alpha_i F_{i,j}}.
\]

直觉是对预测敏感的参数应获得更高保护权重。Fisher 来自数据上的梯度或已有统计。原文以相同架构、相同初始化为背景；它不含自动置换对齐步骤，不能仅因公式没有 θ₀ 就称为无共同起点的通用解法。[原文](https://arxiv.org/abs/2111.09832)

**RegMean。** 若线性层写作 XW，用 Gᵢ=XᵢᵀXᵢ，理想化闭式式子为 Wₘ=(ΣGᵢ)⁻¹ΣGᵢWᵢ；实际方法还处理非对角项等数值问题。目标是使融合后的层输出接近专家输出。“Dataless”是可以只共享预计算统计，不是这些统计从未用过数据。URS 的解码状态分布会随策略改变，不能默认各专家面对完全相同的层输入。[原文](https://arxiv.org/abs/2212.09849)

**WUDI。** 以层增量 τᵢ 的行空间代理任务输入方向，逐层优化：

\[
L(\tau_m)=\sum_i\frac{\| (\tau_m-\tau_i)\tau_i^\top\|_F^2}{\|\tau_i\|_F^2}.
\]

它不需要输入样本，却需要优化合并增量；论文实际使用 Adam。因此 data-free 不等于 gradient-free。其依据涉及微调时层输入的相对稳定性，不能自动套到随机起点长程 RL 训练。[原文 §3](https://arxiv.org/html/2503.08099v2#S3)

回答你对 a=b=1 的追问：人为设 τ₁=[1,0]、τ₂=[0,1]，候选 τₘ=[a,b]。代入该目标得到 (a−1)²＋(b−1)²，两项同时为零的解才是 a=b=1。这来自这个正交玩具例子的条件，不是所有专家的合并系数都应该设成 1，也不证明真实网络无损合并。

**TSV-Merge。** 每层 Δᵢ=UᵢΣᵢVᵢᵀ，保留一部分奇异方向；把多个任务的左右方向拼接，进行最近正交矩阵处理，再重构合并矩阵并加回 base。TSV-C 是压缩，TSV-M 是融合，二者不能混称。矩阵相加和展平成向量再相加原本等价；TSV 的区别在于使用低秩结构筛选及重构。方向重叠可能也是共享知识，不宜把所有重叠都解释为有害。[原文 Algorithm 1](https://arxiv.org/html/2412.00081v3)

## 6. 独立训练模型是否先需要对齐

**Git Re-Basin。** 对网络隐藏单元做协调置换，使一个模型在不改变函数的情况下更接近另一个模型，再做参数融合。论文区分权重匹配、激活匹配与 STE，不能把所有版本都说成需要或不需要数据。URS 的残差、注意力和超网络有关联参数，不能对每个矩阵各自排序后就宣称功能保持。[原文](https://arxiv.org/abs/2209.04836)

**OT Fusion。** 用最优传输矩阵建立神经元对应，再融合权重；相较一对一置换，可形成软匹配并处理不同宽度。匹配成本来自权重还是激活会改变数据需求。论文在视觉网络的成功不是 URS 架构适用性的证明。[原文](https://arxiv.org/abs/1910.05653)

**ZipIt!。** 不只匹配两模型间的特征，也允许合并同一个模型内部的冗余特征；按激活相关性压缩组合。部分 zipping 保留后端多个任务分支，是论文有效设计之一，但应检查它是否满足你“一套固定参数、固定大小”的具体要求。[原文](https://arxiv.org/abs/2305.03053)

**REPAIR。** 指出即使神经元已对齐，参数插值仍可能造成中间激活方差下降；通过统计校正修复。这提示“找到置换”不是结束，但不能未经测量就说 URS 平均失败的原因已经确定是方差塌缩。[原文](https://arxiv.org/abs/2211.08403)

## 7. 系数与规则怎样自动确定

**AdaMerging。** 冻结专家，通过 θₘˡ=θ₀ˡ＋Σᵢλᵢˡτᵢˡ 学任务级或层级系数；原论文用无标签图像的分类预测熵，反传只更新融合系数。AdaMerging++ 先做 TIES 式处理。系数学好后可以固定形成一个模型，不必是随每个实例变化的路由器。[原文](https://arxiv.org/abs/2310.02575)

你追问的 x 在原实验中就是一张待分类图像，不是参数向量。若迁移到 CVRP，x 可以是一个完整实例：客户/仓库坐标、需求、容量；在 CVRPTW 中还含时间窗等。解码到第 t 步的剩余容量、已访问集合等属于状态 sₜ。降低动作分布熵只会让策略更确定，不保证路线更短。改用实际成本可无需最优标签，但离散采样/argmax 不能直接当普通可微函数；需要另行定义梯度估计或搜索方法，属于移植设计而非原 AdaMerging 的现成结论。

**Evolutionary Recipes。** 在预先规定的参数融合配方和数据流路径空间中，按任务指标进化搜索。参数空间可以搜索逐层权重、稀疏度；数据流空间可以选择、重排或重复模型层，可能改变大小和推理成本。它搜索配方，CEMM 则让 LLM 写程序并更新源模型种群；两者都是自动化，但搜索对象不同。[原文](https://arxiv.org/abs/2403.13187)、[正式出版页](https://www.nature.com/articles/s42256-024-00975-8)

**Model Swarms。** 把专家参数作为粒子，结合当前速度、个体最佳和群体最佳位置更新；用任务 utility 决定好坏。无需对任务 loss 反传，不表示不用数据或没有搜索成本；参数空间移动也不会自动解决异源模型的排列问题。[原文](https://proceedings.mlr.press/v267/feng25o.html)

**GENOME。** 通过交叉、变异、评价和选择演化模型群体。原 GENOME+ 还加入历史经验继承与多模型预测集成，因此不能把“+”全部当作更强的单次参数融合公式。[原文](https://aclanthology.org/2026.acl-long.2044/)

**CEMM。** 同时演化合并程序和“通用＋专家”模型角色，按逐任务改善保留程序的互补性。它是直接相关先例，并不意味着当前必须采用 LLM。论文/代码中的训练起点、输入 prompt、算法 2 的范数目标和多模型“+”，见 [专项核对](CEMM_READING.md)。

SLERP 是球面插值算子，可在工具实现中查到。它改变权重插值路径，并不自动解决任务知识冲突；本整理不把它算作另一篇已经核实的独立论文。

## 9. 怎样把文献用于当前工作

最值得沿用的不是“方法名单越长越好”，而是每次明确：当前要解决的是坐标不兼容、更新冲突、行为损伤，还是系数选择问题。

已有原协议结果和同组候选 base 允许继续做有明确标签的探索。TA/TIES/DARE 可以回答简单增量规则能否改善；PCB/TSV/WUDI 提供选择性和行为保持的不同解释；Git Re-Basin/OT/ZipIt 研究另一层的对齐问题；AdaMerging 与搜索方法则需要明确额外信息和目标。使用原数据进行适配/搜索时，应如实记录数据用途，不称为完全未接触评估实例的静态合并；本整理不新增数据划分。

不能仅把上述几种机制堆在一起当作贡献，也不能仅用“更细粒度”区分 CEMM，因为程序搜索可以产生细粒度规则。应由 URS 的实际失效证据决定后续实现，再用单模型、逐任务结果判断是否确实保住了专家能力。
