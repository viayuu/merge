                                                     A      Implementation Details
All task-aligned expert models are obtained by fine-tuning the checkpoint (Berto et al. 2025) at the 270th epoch for 30 additional
epochs on each task. Each epoch consists of 100K VRP instances. We utilized the Adam optimizer with a learning rate of
3 × 10−5 and set the batch sizes to 256 and 128 for n = 50 and n = 100, respectively. The learning rate was decayed by a
factor of 0.1 during the final 5 epochs. In Figure 1, we visualize the performance (ranking) of the five initial expert models based
on the RF-TE backbone across all datasets. It is evident that each model exhibits unique strengths, demonstrating that we have
successfully obtained a diverse set of experts.

B.1     Robustness to Different LLMs
To evaluate the robustness to the choice of LLMs, we additionally conducted comparison experiments at (n=50) using two other
LLMs, Gemini-3.1-flash-lite-preview and DeepSeek-V3.2. As shown in Table 1, GPT-4o achieves overall performance slightly
better than Gemini, while being marginally inferior to DeepSeek; however, all three CEMM variants consistently outperform the
SOTA baseline, Genome. These results suggest that the proposed CEMM framework is largely model-agnostic. Although the
quality of generated algorithms may vary with the capability of the underlying LLM, the core effectiveness of the method remains
stable across different backbones. This indicates that the main performance gains come from the co-evolutionary mechanism
rather than dependence on a specific LLM.

                                                                          C       Prompts of CEMM
      Our prompt framework for LLM-generated merge algorithms can be categorized into Exploration (E1, E2) and Exploitation
      (M1, M2). Each strategy is structured around four components: Task Description, Strategy Instructions, Reference Algorithm,
      and Template Program. Below, we detail their underlying principles and present the specific prompts.
       • E1: Population-Level Innovation. This strategy drives global exploration by prompting the LLM to generate entirely
         novel merging paradigms. By reviewing the entire current population, the LLM is instructed to propose algorithms that are
         orthogonal to existing solutions, thereby expanding the search boundary into untouched algorithmic spaces.
                           Prompt for E1

                           Your task is to design a new algorithm for merging the weights of multiple fine-tuned models into a single merged
                           model that integrates knowledge from all models to improve performance. The function must have exactly two inputs:
                            – base: A dictionary representing the pre-trained model’s state_dict, where keys are parameter names and values
                              are parameter tensors.
                            – model_dicts: A list of dictionaries, where each dictionary is a fine-tuned model’s state_dict derived from
                              the same base model. All models in this list must be merged.
                           Each fine-tuned model shares the same parameter structure as base. The function should return one output:
                            – merged: The merged model’s state_dict.
                           Below are all N algorithms currently in the population. The first algorithm includes both its description and code
                           implementation, while the others only include their algorithm descriptions:

    both concept and implementation. The new algorithm should explore a different merging strategy that has not been used
    by any algorithm in the current population.

    {Template Projection}

• E2:Algorithmic Crossover. Acting as an evolutionary crossover operator, this strategy synthesizes a new algorithm by
  integrating insights from two distinct parent algorithms. The LLM is tasked with inheriting conceptual strengths from the
  provided references while establishing a unique implementation form, promoting the recombination of effective merging
  heuristics.

  high-performing ancestor. It instructs the LLM to introduce functional variations or logical adjustments to the existing code
  structure, thereby refining the algorithm’s mechanism without completely discarding its proven core logic.

                                     D    LLM-generated Merging Algorithms
In this section, we demonstrate two model merging algorithms automatically generated during an evolutionary process driven
by LLMs.
                                                 Merging Algorithm 1:
import torch
import copy

def merge_models(base, model_dicts):
    ’’’
    Args:
        base (dict): State dict of the pre-trained (base) model.
         model_dicts (list[dict]): List of fine-tuned model state dicts; all models in this
     list must be merged.
     Returns:
         merged (dict): State dict of the merged model.
     ’’’

     # ---- Initialization ----
     merged = copy.deepcopy(base)

     # ---- Model Merging Loop ----
     for key in base.keys():
         # Create a list of updates for this parameter from all models
         updates = [(model_dict[key] - base[key]) for model_dict in model_dicts]

           # Stack updates to form a tensor for median calculation
           updates_stacked = torch.stack(updates)

           # Calculate the median of the updates
           median_updates = torch.median(updates_stacked, dim=0).values

           # Update the merged model parameter using the median of updates
           merged[key] = base[key] + median_updates

     return merged
   The first algorithm merges models by applying an element-wise median operator to parameter updates obtained from multiple
fine-tuned models. Given a pre-trained base model θ0 and a set of fine-tuned models {θ1 , . . . , θM }, the algorithm first constructs
task-specific update vectors
                                               ∆i = θi − θ0 , i = 1, . . . , M.                                                    (1)
  For each parameter entry p, the merged update is computed as:
                                         ∆⋆ (p) = median (∆1 (p), ∆2 (p), . . . , ∆M (p)) .                                       (2)
  The merged model is then obtained by:
                                                        θmerged = θ0 + ∆⋆ .                                                       (3)
    The median operator provides a robust estimate of the central tendency of task-specific updates. Unlike mean-based merging,
it is less sensitive to extreme coordinate values and therefore suppresses large but inconsistent parameter shifts introduced by
individual fine-tuning processes.
    From an optimization perspective, the median minimizes the sum of absolute deviations:

                                                ∆⋆ (p) ∈ arg min          |∆i (p) − x| .                                          (4)

   As a result, the merged update tends to retain coordinate-wise changes supported by multiple source models while suppressing
extreme task-specific values. This algorithm requires no additional training, introduces no auxiliary parameters, and operates
purely at the parameter level. Its emergence illustrates that the evolutionary process can recover merging rules grounded in
classical robust statistics without explicit human design.
   In contrast to the static statistical rule of the first method, the second merging strategy introduces a dynamic, learning-based
mechanism.
                                                           Merging Algorithm 2:
import torch
import torch.nn.functional as F

def merge_models(base, model_dicts):
    ’’’
    Args:
        base (dict): State dict of the pre-trained (base) model.
        model_dicts (list[dict]): List of fine-tuned model state dicts; all models in this
    list must be merged.
    Returns:
        merged (dict): State dict of the merged model.
    ’’’
     # Initialize the merged model’s state_dict
     merged = {k: base[k].clone() for k in base.keys()}

     # Simple auxiliary model for learning weights
     class WeightNet(torch.nn.Module):
         def __init__(self, input_dim, hidden_dim, output_dim):
             super(WeightNet, self).__init__()
             self.fc1 = torch.nn.Linear(input_dim, hidden_dim)
             self.fc2 = torch.nn.Linear(hidden_dim, output_dim)

          def forward(self, x):
              x = F.relu(self.fc1(x))
              x = F.softmax(self.fc2(x), dim=-1)
              return x

     # Determine the number of models
     n_models = len(model_dicts)

     # Create an auxiliary neural network
     weight_net = WeightNet(n_models, 16, n_models)

     optimizer = torch.optim.Adam(weight_net.parameters(), lr=0.001)

     # Training the auxiliary network
     num_epochs = 100
     for epoch in range(num_epochs):
         total_loss = 0
         for k in base.keys():
             # Stack deltas for each parameter
             deltas = torch.stack([model_dict[k] - base[k] for model_dict in model_dicts])

                # Pass deltas through the weight network
                weights = weight_net(deltas.view(n_models, -1).mean(dim=1))

                # Compute weighted average of deltas
                weighted_delta = torch.sum(weights.view(-1, *([1] * (deltas.dim() - 1))) * deltas
    , dim=0)

                # Compute loss as the negative of average delta magnitude (to learn meaningful
    weights)
                loss = -torch.norm(weighted_delta)
                total_loss += loss

          # Backpropagation
          optimizer.zero_grad()
          total_loss.backward()
          optimizer.step()

    # Apply learned weights to merge models
    with torch.no_grad():
        for k in base.keys():
             deltas = torch.stack([model_dict[k] - base[k] for model_dict in model_dicts])
             weights = weight_net(deltas.view(n_models, -1).mean(dim=1))
             weighted_delta = torch.sum(weights.view(-1, *([1] * (deltas.dim() - 1))) * deltas
    , dim=0)
             merged[k] += weighted_delta

     return merged

E.1   Probing Analysis
At n = 50, we conduct probing experiments on task-specific experts from the RF-TE backbone and their merged models
produced by Genome and CEMM. Following Probing Task 4 in (Zhang et al. 2025), we train a probe on the final encoder
embeddings to predict whether two customer nodes belong to the same optimal route. We construct 20,000 labeled positive and
negative node pairs from n = 50 instances and report AUC across the five VRP variants.
   As shown in Table 3, CEMM matches the task-specific experts in average AUC (0.907) and clearly outperforms Genome
(0.752). Its AUC differs from that of the corresponding expert by at most 0.003 on every variant. These results suggest that
CEMM retains VRP-specific route-structure knowledge after merging.

E.3   Cross-Scale Out-of-Distribution Generalization
We evaluate the RF-TE backbone models obtained at n = 100 on larger n = 200 instances across the same five VRP variants.
As shown in Table 4, CEMM consistently outperforms Genome across all five tasks, while CEMM+ consistently outperforms
Genome+. The average gaps decrease from 7.558% to 7.228% for single-model inference and from 6.833% to 6.335% for
ensemble inference. These results suggest that the models obtained through CEMM exhibit stronger cross-scale generalization
potential.

E.4   Matched Inference Budget
In the default setting, each task-specific expert uses ×8 instance augmentation, whereas CEMM+ and Genome+ evaluate k = 3
models with ×8 augmentation each, resulting in a threefold rollout budget. To match the rollout budget, we increase each
task-specific expert from ×8 to ×24 augmentation via rotational invariance (Kim, Park, and Park 2022), matching the number
of rollouts used by CEMM+. As shown in Table 5, CEMM+ outperforms the experts on all five tasks at n = 50, reducing the
average gap from 1.826% to 1.701%. This indicates that its improvement is not solely attributable to the larger rollout budget.

                                                          F    Broader Impacts
This work may positively impact real-world routing applications, such as logistics, transportation, and manufacturing, by
providing a robust generalist neural solver for multiple VRP variants and reducing the need to train and deploy separate task-
specific models. However, the LLM-driven evolutionary process introduces additional computational overhead, which may
increase financial costs and raise sustainability concerns due to associated carbon emissions. Future work will explore more
efficient LLM-driven operators to mitigate these potential drawbacks.
