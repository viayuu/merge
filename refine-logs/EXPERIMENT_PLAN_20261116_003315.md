# URS 单任务模型合并：最小判别实验方案

日期：2026-11-16。状态：待实施，无新实验结果。完整证据见 [调研报告](../idea-stage/IDEA_REPORT.md)。

## 要检验什么

**H1：** 仅使用已发布 URS 单任务专家，能否离线合出一个参数量不增加的固定模型，在同样解码预算下接近 URS 通用模型？

**H2（通过 H1 后）：** 专家数量从 2、4 增至 11 时，这种能力是否仍能保留？99 个未见任务是后续泛化测试，不能由 seen-task 结果直接推出。

这是一组可行性实验。暂不证明从头训练总成本更低、普遍优于多任务训练、或方法具备足够论文创新性。11 个现有专家的历史训练成本和本次合并的边际成本分开列。

## 1. 固定对象与两条轨道

主轨 A：只用 `URS/pretrained/*_checkpoint_300.pt` 的 11 个发布专家，输出单一 `model_state_dict`。`unified_checkpoint_500.pt` 只作对照，不充当虚构底座、不混入 merge。每个候选 checkpoint 的权重跨任务完全相同；只保留 URS 原有任务输入、条件参数生成和环境 mask。

后备轨 B：若缺少可验证的共同起点且 A 失败，可以另训练共享起点的少量专家研究 merge 条件。必须独立标注新增训练成本、原始 base 的训练任务、随机初始化或预训练初始化；B 成功不能改写成“发布专家直接合并成功”。若以通用 URS 初始化，则只能称通用模型微调后回并的控制实验。

## 2. 数据与指标先固定

每个目标任务使用原 URS generator 生成两份固定实例：calibration 256 例，final test 1,000 例，N=100。建议 seed 分别 20261116、20261117，另保存每任务 seed 派生规则、生成器版本、输入文件和实例 ID。11 个源任务的生成路径已静态核实；ATSP 复用环境的 `int_min=0,int_max=1000000,scaler=1000000`，其他任务记录容量和分布参数。生成失败或不支持的任务应在 B0 显式处理，不用别的分布静默替代。校准、最终测试、公开数据文件必须相互独立；先落盘再运行模型。

64 例固定 calibration 子集做粗筛，256 例做最终配置选择。B1/B2 和 B3 的候选筛选/停走决策都只看 calibration；final test 文件保持封存，待全部待报告候选、方法和系数冻结后统一评测一次。先在 calibration 上预选一个 H1 主候选：满足观测可行率100%及最差任务退化≤3%的候选中取宏平均退化最小者，同值优先简单方法；没有合格者就记录当前校准阶段未找到主候选。其余冻结方法完整报告为对照，不能在 test 上另挑任意一个过线方法替代主候选来宣布总体成功。若小任务阶段已揭盲其 final test，后续由该结果驱动的修改必须另生成新 held-out，不能复用旧 test 作确认。公开发布 N=100 数据另作为与论文设置接近的补充结果，不能默认其未参与原 checkpoint 的模型选择。

URS 默认 validation/test 代码会取相同目录前 1,000 例，且若干参考值为全文件均值或硬编码常数。新 wrapper 必须保存逐实例原始目标值、方向、可行性、耗时、checkpoint、实例 ID、解码配置；参考解能可靠按 ID 对齐时才额外计算 optimality/reference gap。不沿用不匹配子集的原始 gap。

令 U 为通用 URS、M 为合并模型。在每一任务的同一实例上定义相对退化，单位为百分比：

$$d_{t,i}=100\frac{f_M(x_{t,i})-f_U(x_{t,i})}{|f_U(x_{t,i})|}\quad\text{（最小化）}$$

$$d_{t,i}=100\frac{f_U(x_{t,i})-f_M(x_{t,i})}{|f_U(x_{t,i})|}\quad\text{（最大化）}$$

OP/AOP 使用正 prize，方向为最大化；其余任务按实际环境目标定义，PCTSP 的 penalty 必须计入。**正值越大越差，负值表示优于 URS。** 不使用“先平均目标值再算比值”替代此定义。对分母为零的实例单列绝对差和计数，不悄悄加 epsilon 后纳入宏平均。

每任务先对实例平均，再对任务等权宏平均；同时报告最差任务退化、每任务相对本任务 specialist 的退化、可行率和失败计数。不同任务不能直接平均原始 route length/prize。任一模型的非法解、NaN、未结束 rollout 不得从统计中删除；该候选不满足成功条件，并单列失败。路径合法性要独立检查访问、容量、时间窗、PD 先后等适用条件，环境 mask 本身不等于完整验证。

用 2,000 次按任务分层的 paired instance bootstrap 计算宏平均及每任务 95% CI；每次重采样中 M/U 保持同实例配对，固定这组任务，不把任务数当作训练 seed 数。非对称任务先算每实例、每随机输入的 d(t,i,r)，再对预定3组 r 求均值得到实例级 d(t,i)。bootstrap 只重采样实例 ID，并带走该实例全部3组 M/U 配对结果；1,000实例×3组输入仍是1,000个独立实例。CI 条件于这3组固定随机输入，另报每输入seed结果及极差。对称确定性任务只用1组，不重复计算。

确定性 merge 无须伪造3个训练seed。DARE mask seed=0 为事前确定的主checkpoint，1、2为稳定性检查；每个checkpoint分别沿用上述配对评测/CI，不把3个mask当成额外独立实例，不挑最好seed。只有3个mask均满足可行率与接近标准时，才称随机稀疏合并结果稳定，否则报告其波动。

## 3. 预先定义“差距不大”

以下是本项目建议阈值，不是领域公认标准，也不是已有结果：

| 判定 | 必须满足 | 能支持的结论 |
|---|---|---|
| 强正信号 | 观测可行率 100%；宏平均退化的 95% CI 上界 < 0；无单任务退化超过 3% | 该任务集合/实例分布/预算下优于 URS |
| 可行信号 | 观测可行率 100%；宏平均退化的 95% CI 上界 ≤ 1%；最差任务平均退化 ≤ 3% | 在预定义容忍度内接近 URS，值得继续 |
| 弱信号 | 点估计接近但 CI 仍跨越 1%，或有任务明显退化 | 样本证据不足或任务干扰，需要定位 |
| 负信号 | 公平设置下明显退化/失败 | 当前专家组合和合并算法不成功；不否定全部 merge |

最差任务 3% 是点估计守门条件，每任务 CI 仍完整报告；不把它说成所有任务同时置信的非劣性保证。2/4 任务通过仅支持子集，11 任务通过才支持完整 seen-task motivation。

## 4. 方法顺序与参数

| 方法 | 首轮设置 | 可用前提 / 数据使用 |
|---|---|---|
| Uniform average | 全部浮点模型参数等权平均；全参数同一规则 | 无需知道 base；数学可算不保证坐标对齐或有效 |
| 两模型线性插值 | alpha=0, 0.25, 0.5, 0.75, 1；一个系数服务所有任务 | calibration 选全局 alpha；两端是原专家，不能把端点成功计为多专家融合证据 |
| Task Arithmetic | theta0 + lambda sum(theta_i-theta0)；lambda∈{0.5/K,1/K,2/K,0.5,1}，去重 | 真实共同 base 可验证时才运行标准版本；共同随机初始化另标为外推 |
| TIES | 固定点 retain=20%, lambda=1；再试 retain∈{20,50,100}%, lambda∈{0.5,1,1.5} | 对 task delta 裁剪、幅度选符号、同符号非零均值；需真实 base |
| DARE+TA | drop∈{0,0.1,0.3,0.5}，TA 系数先冻结；最终 mask seeds=0,1,2 | 先做单专家 drop 检验；需真实 base；第二批运行 |

以上网格为本项目建议。固定超参结果与 calibration-tuned 结果分表；记录候选数、总验证推理量和搜索时间，不声称调参开销相等。TIES 使用同符号均值，其 lambda 不能直接照搬采用求和的 TA 尺度。DARE 先随机丢弃 delta，再以 1/(1-p) 缩放；不是直接丢原始权重。

若无真 base，首轮只运行平均/插值；TA/TIES/DARE 明确记 `NOT_APPLICABLE_BASE_UNVERIFIED`，不能任取专家、均值或 URS 通用模型冒充历史共同起点。后续 Fisher/RegMean 需要统计或校准数据；Git Re-Basin 需要 URS 专门的功能保持排列规范；不将它们当作无条件补救。本轮不安排大规模 merge 方法排行榜。

## 5. 五个实验块

| 块 | 任务与对象 | 关键对照/产物 | 决策 |
|---|---|---|---|
| B0 前置核验 | 12 个 checkpoint，N=100 小样本 | 参数 key/shape、谱系；U/专家可运行；新数据；逐例目标值与合法性 | 先解决数据/评测问题再比较模型 |
| B1 两专家 | cvrp+cvrptw；另一组 tsp+atsp 作为结构差异诊断 | U、两个单专家跨两个任务、uniform、5 点插值；base 存在才 TA/TIES | 检查是否只保留了一个专家；负结果不外推全部 11 |
| B2 四专家 | cvrp,cvrpb,cvrptw,ocvrp | U、4 个专家各测4任务、uniform、可用的 TA/TIES/DARE | 任务均值/最差任务及4×4专家能力表 |
| B3 完整 seen | tsp,atsp,cvrp,acvrp,cvrpb,cvrptw,ocvrp,ocvrptw,op,pctsp,pdtsp | U、11 专家各测11任务、uniform、每个可用方法冻结的最佳配置 | 11任务主表；只有该块通过才回答完整 motivation |
| B4 泛化扩展 | 其余99任务；大规模实例与基准库另列 | 冻结 B3 配置，只做评测；不在99任务调参；多仓新数据入口尚不支持，需单独补齐或明确使用公开集 | 支持 unseen generalization，非最小 motivation 必需 |

B1/B2 使用预先选定的任务子集，不因测试结果临时换更容易的任务。B3 的 11×11 专家交叉评估先在 calibration 完成；final test 至少保留每任务本任务专家、由 calibration 选出的“全任务最佳单专家”、U 与候选合并模型。专家按任务切换是存储 11 个模型的参考系统，不能标成单模型 baseline；逐实例 best-of-experts 是更昂贵的 oracle，不是免费公平对照。

单独判断能力融合归因：若 merge 接近 U，但没有超过 calibration 选出的最佳固定单专家，H1 的部署可行性仍可能成立，却不足以证明合并带来额外多任务收益。两专家阶段应检查各自优势任务是否互补、内点合并是否保留两边优势；端点或纯单专家已满足相同标准时，如实报告“未显示合并增益”。

若 B1 完全失败，仍在小 calibration 上检查 uniform-4/11，避免两任务个例决定整个方向；随后才考虑谱系/对齐诊断或轨 B。若普通平均已满足 H1，先完成 B3，不急着增加机制。

## 6. 解码与计算公平性

主比较先使用 `eval_type=greedy`、关闭 augmentation，但沿用 URS 的 POMO 多起点。它不是单条 greedy trajectory。记录实际每任务 POMO 数（一般 N=100 为100，PD为50，backhaul/多仓不同）并保证同任务各模型一致。

补充结果恢复 URS 标准增强：对称8、非对称128。不同任务预算可以按 URS 定义不同，同任务内 U/专家/merge 必须完全一致。不能拿无增强 merge 对照增强 URS，也不能用更大的搜索预算掩盖模型退化。先冻结权重再切换到补充增强设置；它不改变主结果。

非对称模型即使 greedy 也会随机生成 node IDs（`Model_LIB.py:208–215`）。必须缓存每例随机 ID/增强输入并对所有 checkpoint 复用，或验证相同 RNG 状态、批切分和任务顺序确实产生相同输入。首次正式结果对3组预先固定的随机输入种子作配对评测，所有方法使用同一组；单种子筛查只作筛查，不能把差异误归因于 merge。它与 DARE 的 mask seed 是两个不同随机来源，分别记录。

同一机器、同一精度、相同 batch 配置，显存不足时所有对照统一调小。计时先 warmup、同步 CUDA；分开模型加载、合并时间和稳态推理。保存参数量、单模型权重字节数、峰值显存、每例时间，不用含 optimizer 的 checkpoint 文件大小代替部署大小。

不设置用户已取消的时间/GPU小时上限。当前会话的 `nvidia-smi` 无法与驱动通信；这仅表示本次 shell 尚未确认 GPU 可用，规划不受影响。实施前确认设备可见与 `torch.cuda.is_available()`，本轮不修改驱动。运行放 tmux。GPU小时不作无依据预估，先用32/64例测每任务耗时，再按 实例数×配置数×seed数×实际起点/增强预算 估算。

## 7. 实施文件与最先三步

建议新增独立目录 `merge_lab/`，不把实验逻辑塞进 URS 原训练脚本：

- `audit_checkpoints.py`：记录来源、模型 key/shape、dtype、训练元信息及共同 base 证据。只加载模型 tensor，合并不含 optimizer。
- `merge_checkpoints.py`：uniform/interpolation；满足 base 前提后实现 TA/TIES/DARE；输出 manifest 与 strict-loadable checkpoint。
- `evaluate.py`：复用 URS 模型/环境，外置数据 split 和逐实例记录；独立路径合法性检查。
- `summarize.py`：方向统一、paired CI、11任务表、任务数扩展曲线。

这些文件是实施计划，目前尚未创建。实现时必要正确性检查：单输入 average 恒等；alpha 两端恒等；TA lambda=1/K 与 average 数值一致；DARE p=0 与底层合并器一致；非浮点 buffer 不盲目平均；TIES 零向量/平票约定清楚。与 URS 原 evaluator 在同一小样本上核对目标值和路线。

第一步完成两任务所需的 B0；第二步先用各64例 calibration 运行 cvrp+cvrptw 的两个专家、U和0.5平均，共4个唯一模型，再只补0.25/0.75插值并复用端点结果；第三步扩至四专家并冻结进入11任务的候选。其他任务的评测核验随扩展完成，无须先建设99任务评测。单任务重训不能直接传 `train.py --problem_set cvrp`：当前训练入口固定 `train_problem_list`，该参数主要用于测试；轨 B 必须明确增加或包裹训练任务列表。
