## 按重要性排列的可执行意见

### 1. 三个随机输入重复如何进入主指标和 bootstrap：已解决

位置：`EXPERIMENT_PLAN.md` 第2节第27–37行，第6节非对称随机输入段。

初稿规定对非对称任务使用三个预固定随机输入种子，并且进行实例级配对 bootstrap，方向正确，但没有明确如何聚合这三个重复。实现者若把同一实例的三次输入当作三条独立实例，区间会被错误收窄；若先平均目标再算比例，则改变已经固定的指标。

建议的最小补充已写入最终计划第37行，内容为：

> 对具有随机 node IDs 的任务，按原公式计算每实例、每随机输入的退化 `d[t,i,r]`，先对同一实例的三个预固定输入取均值，得到 `d_bar[t,i]`，再按实例和任务等权汇总。Bootstrap 只重采样实例 ID，每次一起带走该实例全部三个 M/U 配对结果，不能把三个重复当作三个独立实例。该 CI 条件于预固定的三个随机输入集合；另列各输入 seed 的结果及极差。确定性任务使用一个输入设置，不为形式上的“三个 seed”重复计算。

这不要求嵌套 bootstrap 或更多 seed；先给出条件于固定输入集合的清楚结论就足够。单种子64例筛查仍可保留。

### 2. 最终主候选：非阻断性报告建议

位置：`EXPERIMENT_PLAN.md` 第3节判定表，第5节 B3 行及第76行。

逐方法在 calibration 内选超参、冻结后完整报告，是正确方案。若同时报告多个 merge 方法，则“它们中只要有一个95% CI过线，就宣布总体成功”会引入另一次测试集选择。当前文本没有明确打算这样做，所以这是需要防止的解释歧义，不能说已发生多重检验错误。

最小修正是在 calibration 上按既定宏平均指标、可行性和最差任务条件预选一个主候选；把它用于 H1 的主要确认，其余冻结方法完整列为对照。无需为这个 motivation pilot 新增大规模多重比较程序。没有真实 base 时，候选数量本来就很小；先均匀平均与插值完全合理。

### 3. DARE 的多个 mask 只能作为多个固定模型重复：已解决

位置：`EXPERIMENT_PLAN.md` 第2节第39行，第4节 DARE+TA 行。

最终计划明确事前固定 mask seed=0 为主checkpoint，1、2作稳定性检查，分别评估/计算CI，不池化成额外独立实例，不挑最好seed；三个都满足预定可行性与接近条件才称稳定。该修正充分解决了单模型部署结果与随机方法重复统计的混淆风险。

这一项不影响当前无已验证 base 的平均/插值首轮，也不应成为现在增加工作量的理由。

## 最小首实验的执行解释

不需要重写实验路线。建议把已有 B0+B1 落成以下最小切片：

1. 先确认 GPU 可见。复用已有 CPU strict-load 证据，完成 CVRP/CVRPTW 两任务小样本的目标值、路线、终止和约束核对；其余任务的 evaluator 核对可随 B2/B3 逐步补齐，不必先完成99任务基础设施。
2. 固定两任务各64例 calibration，N=100、greedy+POMO、关闭增强；运行 U、CVRP专家、CVRPTW专家、0.5平均这四个唯一模型。得到两个单专家的2×2能力表、平均相对U/单专家的逐例变化、可行性和实际耗时。此时只做诊断，不从64例宣布H1成立。
3. 若继续插值，只补 alpha=0.25、0.75；alpha=0、0.5、1的已有模型结果复用，避免重复计算。使用256例 calibration 冻结选择。没有真实 base 就不启动 TA/TIES/DARE。
4. B1/B2 的扩展与停走全部使用 calibration；B1失败时保留既定 uniform-4/11 的小样本排查。final test 继续封存，直到全部主候选及对照定义冻结。

首次两任务均为对称问题，所以非对称三个输入的实现不会拖住这一切片。在 TSP+ATSP 诊断或含 ATSP/ACVRP 的正式确认中，落实计划现已明确的统计规则即可。
